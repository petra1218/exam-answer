# 答案册规范

执行"出答案册 <课程名>"时读。本文只讲怎么产出文稿，不涉及任何真实课程内容，例子都是虚构的。

## 一、定位

答案册是考前准备物：把每门课可能考的题先答好、口径先统一，考场上直接调用、按题面微调。谁都能用本指令生成，生成结果由用户自己粘贴到腾讯文档，本技能不自动写入腾讯文档。

## 二、流程

1. 先执行"开考 <课程名> 全量"，讲义全部装进上下文。
2. 用户提供了往届试题：逐题收入，按讲义重新作答，不照抄往届答案。往届答案只用来对照题型，不用来抄内容。
3. 按课次列预测题：每课次 3 到 5 题。选题优先级：
   第一优先：讲义里写明"老师强调""考试重点""容易错"的内容。
   第二优先：讲义里出现两次以上的模型、公式、对比。
   第三优先：讲义里独有的案例结论。
4. 题型分布：参照往届试题的题型比例；没有往届题就按简答 4 成、结合本企业 2 成、选择 2 成、计算 2 成配置。计算题只在有计算内容的课次出。
5. 每题按 references/题型模板.md 的范式写答案；计算题按 references/计算题写法.md 的四行写法写。
6. 选择题集中放在文稿末尾，另出一份口径表。

## 三、自检（写完每题过一遍）

1. 依据检查：每个要点都能在讲义或课件里找到出处。找不到的删掉或换成有依据的要点。
2. 冲突检查：和老师讲法冲突的通用说法不收。判断方法——讲义和通行教材说法不一致时，以讲义为准；冲突点本身往往就是考点，收进口径表。
3. 范式检查：按题型模板的自检方法执行。
4. 计算检查：每个数值用 references/计算命令与系数表.md 的命令或静态表核对。

自检不过的题重写，不降标准收编。

## 四、口径表规则

只收课堂上特有的说法，每条一句话。三类来源：

1. 老师自己的定义：讲义里对概念的口径和通行说法不同的。
2. 案例的结论：讲义里案例给出的、可以当判断依据的结论。
3. 和通行说法不一样的点：通行教材说 A、课堂说 B 的地方。

不收：通用知识点、与通行说法一致的常规表述。

## 五、输出格式

一份 Markdown 文稿，两个一级标题：

    # <课程> 答案册

    ## 往届试题（如有）
    题目 + 答案

    ## 课次预测
    ### 01 第X课次 <课次标题>
    题目 + 答案
    （每课次 3 到 5 题）

    # <课程> 口径表

    - <课堂特有说法一句话>
    - <……>

注意：答案册里的答案可以带 Markdown 标题结构（它是文档不是答卷）；但每题答案正文仍按题型模板的纯文本范式写，保证考场引用时不用二次清理格式。

## 六、虚构示例片段

    # 软件项目管理 答案册

    ## 课次预测
    ### 05 1024 工作分解结构

    预测题 1（简答）：什么是工作分解结构？分解到什么程度为止？

    工作分解结构是把项目可交付成果逐层分解成更小单元的层级工具，最底层是工作包，由一个人负责，能估算工期和费用。

    分解时按可交付成果分，不按职能部门分。

    分到工作包为止，再往下是活动，活动归进度计划管。

    # 软件项目管理 口径表

    - 老师口径：WBS 最底层叫工作包，不叫活动。
    - 案例结论：该项目的范围蔓延源自客户方需求变更流程缺失。
