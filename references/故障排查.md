# 故障排查

工具调用失败、读不到、输出被切掉、截断、缓存写不进时读。每条：现象、缺什么、去哪里补、补完从哪一步重试。

先分清走的是哪条路：WorkBuddy 快通道用 tencent-docs 技能自带的 tencentdocs.py（描述为"腾讯文档 MCP 调用入口"），命令形式见 SKILL.md"能力与入口"；其他 agent 走通用路径，工具名认功能不认名字，按功能找列目录、读正文、取账号。快通道脚本找不到或命令报错时回退通用路径，见第 13 条。

只有落地和更新资料才连腾讯文档。答题读的是本机缓存，本机缓存出问题看第 14、15 条。

## 1. 腾讯文档没接上（含会话工具列表里找不到工具）

现象：宿主连接器状态不是 connected、tdoc_init 不返回 READY，或通用路径下会话工具列表里找不到能列目录、读正文的腾讯文档工具。
缺什么：当前 agent 没接入腾讯文档能力。
去哪里补：
- WorkBuddy：只说一句"需要腾讯文档连接器"，让宿主弹出引导卡片，授权后自动继续当前任务；不要在答复里写配置步骤，也不要因此直接判"资料未覆盖"就按通用知识作答。
- 其他 agent：在它的 MCP 配置里添加腾讯文档 MCP 服务器。
补完从哪一步重试：自检第 2 步，或"答题"自动落地第 2 步。
注意：连接器已是连接状态、能力却没被使用，属于流程问题，不是没接上；按"答题"自动落地重走一遍，别标"把握：低"。这门课已经落地过的，直接读本机，根本不需要这一段。

## 2. 取账号失败

现象：取账号工具报鉴权失败或令牌过期。
缺什么：腾讯文档登录态。
去哪里补：在宿主 agent 里重新授权或重新登录腾讯文档连接器。
补完从哪一步重试：自检第 3 步。

## 3. 列目录无权限

现象：列目录报权限错误，或返回空列表但用户说里面有东西。
缺什么：这个文件夹对当前登录的账号没有读取权限。共享链接 ≠ 当前账号有权限，链接分享范围可能不含此账号。
去哪里补：让资料主人把共享权限开到当前登录腾讯文档的账号，或让用户用有权限的账号登录。
补完从哪一步重试：自检第 5 步，或"准备考试"第 2 步。
注意：不要反复重试同一个无权限链接，权限没变结果不会变。

## 4. 工具输出中途被切掉（JSON 不完整、结尾突然断开）

现象：一次调用返回超大，输出从中间断开，JSON 解析不了，或结尾没有正常收束。
缺什么：单次工具输出有上限，一次递归列多层目录会把返回撑爆；浅层列举每页很小，不会撞。别的 agent 上限可能不同。
去哪里补：先看返回的 truncated 字段。为 true 说明本页被截断，这次调用作废，不要拿半截结果用；改用浅层列举（不带 max_depth，每页 20 条），或一次读更少的篇数。finish 为 false 只是还有下一页，把 start 加 20 再列即可，不是截断。翻到空页（返回 0 条）就停，即使 finish 仍是 false——条目数正好是 20 倍时 finish 可能一直为 false，别死循环。
补完从哪一步重试：自检第 5 步、"准备考试"第 3 步或第 4 步，按作废的那次调用是哪一步来定。第 4 步撞上限就把每轮并行篇数从 10 篇降到 5 篇，别降到一篇一篇来。

## 5. 课程文件夹找不到

现象：自动发现没找到用户说的课程名，或资料源里没有这门课。
缺什么：课程名对不上，或链接、搜索关键字取错。
去哪里补：按 SKILL.md"资料源自动发现"的顺序重来——先看消息里的链接、再看 `~/.exam-answer/资料源.txt`、再按课程名用 manage.search_file 只搜文件夹（only_folder 为 true）、最后不传 folder_id 列根目录挑符合识别表的课程文件夹。课程名用包含匹配，简称或部分字样也能对上完整课程名；仍对不上就列出实际有哪些课程让用户确认；多个资料源时逐个查完再报。链接最后一段是 folder_id，search_file 返回的是 file_id，别取错。
补完从哪一步重试："准备考试"第 2 步。如果本机已经有这门课的缓存，先直接用它答题，别卡在找不到文件夹上。

## 6. 讲义读不到或读出来是空的

现象：get_content 返回空、报错或明显不是讲义内容。
缺什么：单篇文档权限、文档类型不支持、或 file_id 取错。
去哪里补：换目录里该文档的 id 重试一次；仍失败就跳过这篇，清单里状态写"未落地"，不阻断其余篇目落地。实测偶发读超时，重试即恢复。
补完从哪一步重试："准备考试"第 4 步。

## 7. 长文档读不全（截断）

现象：get_content 只有 file_id，没有分页参数，也没有截断标志；超过上限只拿到开头（约 1.6 万汉字）。PDF 正文里带 `<!-- page N -->` 页标记，读到第几页看标记；一个页标记都没有的，可能没有完整读出。
缺什么：工具侧对单次输出的截断，不是权限问题。
去哪里补：按 SKILL.md"读取"一节的截断统一处理——读到多少就落地多少，清单里状态写"可能不全"、注明卡在哪，继续其余篇目。PDF 报"读到第 N 页"并请用户对照实际页数。超过 60 页的在线幻灯片改用 slide_get_page_info 按页读，每轮并行 20 页，读到够回答就停（整篇读幻灯片没有页标记，243 页章节整篇读会超限）。
补完从哪一步重试："准备考试"第 4 步继续落地其余篇目。只有落地后已经无法稳定作答才整体改用精简模式，见下一条。

## 8. 落地后作答仍不稳（前后文丢失、工具报超长）

现象：读本机文件时上下文吃紧，输出质量下降，或工具报超长。
缺什么：上下文容量，不是资料不全——资料已经在本机，随时可以再读一次。
去哪里补：改用精简模式，只留清单和导览在上下文，讲义一律答题时按需检索着读。告诉用户改了模式。多门课同时开考时改成一门一门来。
补完从哪一步重试："开考"第 2 步（精简模式，只留清单和导览在上下文，讲义按题检索）。
注意：单篇截断不触发本条，按第 7 条处理，别一遇截断就改精简。

## 9. 照片看不清

现象：题面数字、单位、选项糊或反光。
缺什么：图像质量。
去哪里补：用【?】标出看不清的字，在答复开头集中列出问用户。数字和选项读两遍，宁问勿猜。
补完从哪一步重试：答题第 1 步（用户回复后重新转写该处）。

## 10. 答案册生成中断

现象：出答案册过程中途失败。
缺什么：看具体报错落在上面哪条。
去哪里补：按对应条目处理。
补完从哪一步重试：已写进本机文件的课次保留，从失败的课次继续，不从头重写。

## 11. 沙箱写不进 .exam-answer/（资料源、本人情况）

现象：保存资料源或本人情况时报只读或权限拒绝。
缺什么：文件系统写权限。
去哪里补：这两样不写了。告诉用户每次把链接和本人情况一起发来即可；资料源没写进去不影响按"资料源自动发现"用消息里的链接或按课程名搜文件夹。
补完从哪一步重试："设置资料源"第 2 步降级路径，直接进入"准备考试"。
注意：课程缓存写不进是另一回事，看第 14 条——那个影响更大，因为整个"落地一次、以后读本机"都靠它。

## 12. 个人材料读不了

现象：用户发来报名表、简历一类的 Word、PDF 或图片，读不出来、格式打不开、或工具不支持。
缺什么：agent 这一侧读这份文件的能力，不是用户给错材料。
去哪里补：不猜内容。请用户把材料里的关键事实粘贴成文字，或另存成纯文本、PDF 再发一次；按"设置本人情况"第 3 步的三种给法收。材料只在本次会话里读，不上传、不入库。
补完从哪一步重试："设置资料源"第 3 步（本人情况分支）。

## 13. WorkBuddy 快通道不可用（脚本找不到或命令报错）

现象：找不到 tencentdocs.py、找到的脚本描述对不上、tdoc_init 报错，或 tdoc_call 返回"工具不存在""参数错误"。
缺什么：插件版本目录变了、拿到了同名的其它脚本，或 service、tool、字段名写错。
去哪里补：
- 脚本：只认描述为"腾讯文档 MCP 调用入口"的那个 tencentdocs.py，别写死带版本号的插件目录；插件缓存里同时有 library-office-edit、tencent-docs、tencent-saas-docs 三个同名脚本和新旧两代版本目录，按描述挑。
- 命令：调用前用 tdoc_schema 查参数定义，别猜；service 一律 tencent-docs。字段按 SKILL.md"能力与入口"的桥接表取——search_file 用 file_id，folder_list 的条目用 id，别混。
- 仍不行：回退通用路径——在会话工具列表里按功能找列目录、读正文的工具，或让用户把共享文件夹链接随消息发来。不要因为快通道失败就放弃落地、直接按通用知识作答。
补完从哪一步重试：自检第 2 步，或"答题"自动落地第 2 步。
注意：这门课已经落地过的，快通道坏了也不影响考试，直接读本机。

## 14. 本机缓存路径找不到或写不进

现象：读 `~/.exam-answer/课程/<课程名>/` 时报路径不存在、无权限、磁盘满，或写进去的文件读回来是空的。
缺什么：路径写法不对，或文件系统不允许写。
去哪里补：
- 路径：读文件工具一般要绝对路径，波浪号不一定展开。Windows 用 `C:\Users\<用户名>\.exam-answer\`，macOS 用 `/Users/<用户名>/.exam-answer/`，Linux 用 `/home/<用户名>/.exam-answer/`。不确定用户名就问用户，或列一次用户主目录确认，别猜。
- 权限：换到用户主目录下可写的位置仍不行，就是环境限制，不硬试。
- 磁盘满：报给用户，让他清一下空间再重来。
降级：告诉用户"本机存不下，每次开考还得重拉一遍"，然后按纯会话内装资料的路子走——一次把讲义读进上下文直接答题，不写盘，结果一样，只是下次还要重来。
补完从哪一步重试："准备考试"第 4 步（写盘那一步）。

## 15. 本机缓存可能过期

现象：用户说"老师新发了讲义""资料更新了"，或清单里的抓取时间已经很久，而答案对不上讲义。
缺什么：缓存和腾讯文档之间的同步。缓存只代表抓取那一刻的内容。
去哪里补：执行"更新资料"——重新列一次目录，按 file_id 和 modify_time 比对，只重拉新增和变更的篇目，删除篇的本机文件同步删掉，然后改清单的抓取时间和状态。
补完从哪一步重试："开考"第 2 步重新读清单和导览。
注意：不要在每次开考时都比对一次，那是拿考场时间换一个大概率没变的检查；只有用户说要更新、或者答案明显和讲义对不上时才做。
